# hxwl-11 双眼视功能复训排程

由「眼科验光记录」扩展：双眼视功能评估登记、训练准入复核与训练位排课。

## 技术栈

React 19 + Vite + TypeScript + CSS（无后端，localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev        # http://localhost:5111
npm test           # 类型检查 + 规则冒烟 + 状态机端到端测试
npm run build
```

## 业务规则

- **每次评估登记**：患者、年龄、远距离（5m）/近距离（33cm）水平隐斜（△ EXO/ESO/正位）、调节幅度 AMP（D）、集合近点 NPC（cm）。
- **训练准入**：
  - AMP 低于年龄下限（Hofstetter 最小幅度 `15 − 0.25 × 年龄`）或 NPC 超过 `10cm` → 只能进入**训练待复核**；
  - 待复核评估**必须填写训练方案**才可排课（排课按钮禁用，确认时拦截）。
- **排课占用**：3 个训练位 × 每日 4 节；同一训练位同一时段至多 1 人，同一患者同日至多 1 节；释放后立即可约。
- **冻结与版本链**：评估确认后检查值冻结；更正必须填原因，生成新版本（v1 → v2 …），旧版本标记「已被取代」并完整保留。
- **先释放原时段**：已排课后修改检查值（确认更正）时，依据旧版本排的全部有效课时先释放（记录保留、active=false），再按新版本重新排课。
- **刷新一致**：数据整体原子写入 localStorage，刷新后评估、排课、占用与版本链保持一致（「重置演示数据」可恢复内置示例）。

## 分层结构（数据 / 规则 / 页面分开）

```
src/
├─ domain/            数据层：类型、训练位/时段、日期、ID、种子数据、持久化
│  ├─ types.ts
│  ├─ slots.ts
│  ├─ dates.ts
│  ├─ id.ts
│  ├─ seed.ts
│  └─ storage.ts
├─ rules/             规则层：纯函数，无 React、无存储副作用
│  ├─ clinicalRules.ts   Hofstetter 下限、NPC 阈值、训练准入
│  ├─ bookingRules.ts    时段占用/同日冲突
│  ├─ versionRules.ts    版本链、生效版本、排课状态汇总
│  └─ validation.ts      登记/确认/更正/排课的输入校验
├─ state/
│  └─ store.tsx       状态层：唯一数据入口 reducer（断言兜底不变式）+ Context
├─ ui/                页面层：看板、评估与版本链、排课网格、表单/弹层/Toast
└─ App.tsx            外壳与页签
scripts/             规则冒烟与 reducer 端到端测试（esbuild 打包到 node 运行）
```

页面只做展示与交互编排；阈值、准入、占用、版本判定全部引用 `rules/`，reducer 内断言作为不变式的最后防线。
